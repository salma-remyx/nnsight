# Vision Causal Scan

## What this is for

Ask a VLM about a specific part of an image and the natural assumption is that the vision tokens *inside that region* are what determined the answer. This pattern tests that assumption instead of assuming it: corrupt the image, then restore one region's activations from the clean run and see whether the answer comes back.

The result is often counterintuitive — the regions that restore the answer lie outside the one you asked about. "Where To Look? Causal Tracing of Vision Encoders in VLM" (arXiv:2608.10758) documents this across models and corruption types, and takes it as evidence that strong multimodal performance does not imply spatially localized causal representations.

`nnsight.modeling.CausalScan` runs the sweep for you. It is the same causal-mediation move as [activation-patching](activation-patching.md), applied once per (region, layer) over the vision tower instead of once at a single site.

Adapted from arXiv:2608.10758v1. The per-(region, layer) patching sweep is the paper's method; the benchmark suite is replaced by a next-token log-probability effect size so the sweep runs on any nnsight model.

## When to use

- Asking whether the tokens that drive an answer are the ones inside the queried region.
- Building a causal map over the vision tower: which layer, which patch, carries the answer.
- Comparing corruption types (mask vs. shuffle) to separate "uses the content" from "uses the layout" of a region.
- Sanity-checking attention- or gradient-based saliency: those show correlation, this shows causation.

## Canonical pattern

```python
from nnsight import VisionLanguageModel
from nnsight.modeling import CausalScan, grid_regions
from nnsight.modeling.vision_causal_scan import mask_pixels

model = VisionLanguageModel(
    "llava-hf/llava-interleave-qwen-0.5b-hf", device_map="auto", dispatch=True
)

prompt = "<image>\nWhat color is the traffic light?"

# 336px image at 14px patches -> 24x24 grid of 576 vision tokens.
# Coarse 3x3 regions of 64 tokens each.
regions = grid_regions(n_tokens=576, patch_grid=24, region_grid=3)

# Grab the pixel tensor the processor would produce, so the corruption
# happens in the same space the model sees.
pixels = model.processor(images=[img], return_tensors="pt")["pixel_values"][0]

scan = CausalScan(
    layer_path="model.vision_tower.vision_model.encoder.layers",
    layers=(6, 12, 18),
    regions=regions,
    answer=model.tokenizer.encode(" red")[0],
    target_region=4,                       # the region you asked about
)

# Pass 1: clean run, save every region's activations at every layer.
captured = scan.capture(model, prompt=prompt, images=[img])

# One corrupted image per region: that region's pixels blacked out.
corrupted = {
    region["id"]: mask_pixels(pixels.clone(), region, patch_grid=24)
    for region in regions
}

# Pass 2: patch each region's activations back into its corrupted run.
report = scan.patch(
    model,
    captured,
    prompt=prompt,
    corrupt_kwargs={
        rid: {"prompt": prompt, "images": [corrupt]}
        for rid, corrupt in corrupted.items()
    },
)

print("target region:  ", report.inside.mean())
print("everywhere else:", report.outside.mean())
print("most causal:", report.argmax_region(12)["row"], report.argmax_region(12)["col"])
```

If `report.outside.mean()` rivals or beats `report.inside.mean()`, the answer is being carried by tokens outside the region you asked about — the paper's headline finding.

## How it works

The sweep is two passes, matching the two-pass shape the [ablation](ablation.md) recipe uses for mean ablation:

1. **`capture`** — one clean trace, saving every region's activations at every target layer.
2. **`patch`** — one trace per corrupted condition: an invoke that patches the region in, plus a corrupt-only baseline invoke for comparison.

Each pass is a plain `with model.trace(...):` block, so the captured activations travel between passes as ordinary Python values.

Note the difference from the single-site recipe in [activation-patching](activation-patching.md), which uses two `tracer.invoke` calls joined by a `tracer.barrier(2)`. That works when your trace code runs in your own frame. Here the sweep is generated by library code, and cross-invoke value sharing resolves against the *caller's* frame — `get_non_nnsight_frame()` in `intervention/tracing/util.py` skips frames belonging to the `nnsight` package, so a barrier inside the library cannot hand a value between invokes. Splitting into two passes sidesteps the barrier entirely. The generated trace bodies are registered with `linecache` so nnsight's `inspect.getsourcelines`-based source capture can find them — the same trick `intervention/serialization.py` uses for deserialized functions.

## Variations

### Shuffle instead of mask

[ablation](ablation.md)'s zero/mean/resample distinction applies to the corruption too. Masking drops a region's content; shuffling keeps its pixel statistics and destroys only the layout:

```python
from nnsight.modeling.vision_causal_scan import shuffle_pixels

shuffled = {
    region["id"]: shuffle_pixels(
        pixels.clone(), region, patch_grid=24, generator=torch.Generator().manual_seed(0)
    )
    for region in regions
}
```

If shuffling a region hurts as much as masking it, the model is reading that region's structure, not just its content.

### Token groups on a text model

`CausalScan` is model-agnostic — a "region" is just a list of sequence positions. On a `LanguageModel`, use token-index groups:

```python
regions = [
    {"id": 0, "positions": [1, 2, 3]},   # the subject span
    {"id": 1, "positions": [8]},         # an unrelated control position
]
scan = CausalScan(
    layer_path="transformer.h",
    layers=(5, 7, 9),
    regions=regions,
    answer=model.tokenizer.encode(" Paris")[0],
    target_region=0,
)
```

`tests/test_vision_causal_scan.py` runs the sweep this way, on GPT-2, and checks that restoring the subject span helps the answer more than restoring the control position.

### Sweep only the layers you care about

`layers=` accepts any indices into the module at `layer_path`, including negative ones. Sweeping every layer of a 24-layer vision tower at 9 regions costs 216 patched runs; picking three depths usually answers the question.

## Interpretation tips

- **Always read against the corrupt-only baseline.** The report's effects are differences from that baseline, which is captured in the same trace and included as `report.baselines`.
- **A region can help without being *the* region.** Patching any position at a late layer nudges logits. Compare regions to each other, and to the control, rather than to zero.
- **Early layers tell you about the image, late layers about the answer.** The same region often peaks at different depths depending on whether the question is about appearance or identity.
- **Restoration is an upper bound on sufficiency, not a proof of necessity.** A region whose restoration does nothing may still be needed; try ablating it in the clean run ([ablation](ablation.md)) for the converse test.

## Gotchas

- **The corruption and the patch must target the same region.** `corrupt_kwargs[rid]` describes the run that region `rid` gets patched into. If every entry is identical, the sweep measures pure activation restoration (denoising) rather than corruption recovery — which is a valid experiment, just a different one.
- **`prefix_len` matters.** `grid_regions` counts positions from the first vision token. Leading text or special tokens shift the span; pass their count as `prefix_len`.
- **Patch merging changes the count.** Towers that merge 2x2 patches into one token emit `(patch_grid/2)**2` tokens. Pass the *token* grid side, not the pixel grid side.
- **Tuple outputs need `output_index`.** GPT-2-style blocks in `transformers<5.0` return tuples; pass `output_index=0`. Tensor-output blocks (Qwen2, `transformers>=5.0`) take the default `None`.
- **Module path varies by architecture.** Print the model or check `docs/models/vision-language-model.md` for the vision-tower path before sweeping.
